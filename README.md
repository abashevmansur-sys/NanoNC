Проект NanoNC:
Для любителей самодельных станков ЧПУ, которых напрягает избыточность и дубовость интерфейса FluidNC и потобных ему.
В архиве две папки с проектами и файл apk:
-папка с исходниками на интерфейс ЧПУ станка, написана с использованием VS Code и фреймворком Flutter.
-папка с исходниками на прошивку платы ESP32, написана с использованием VS Code и фреймворком PlatformIO.
-файл NanoNC.apk для установки программы интерфейса станка.

1. УСТАНОВКА ПРШИВКИ:
   при разводке дорожек на плате ESP32 обратите внимание на какие пины выводить драйвера моторов и шпинделя, в моём случае расклад следующий:

1.1 Пины управления двигателями (Stepper Motors):
   Ось X: Шаг (Step) пин 12, Направление (Dir) пин 13.
   Ось Y(1): Шаг (Step 1) пин 14, Направление (Dir 1) пин 27.
   Ось Y(2): Шаг (Step 2) пин 25, Направление (Dir 2) пин 26.
   Ось Z: Шаг (Step) пин 17, Направление (Dir) пин 16.
   Общий для всех драйверов: Включение моторов (Enable) пин 15.
   Шпиндель: пин 4 (поддерживает управление скоростью через ШИМ/analogWrite)

1.2 Пины управления SD картой (SPI):
   CS: пин 5 (Chip Select).
   MOSI: пин 23 (стандарт для ESP32).
   MISO: пин 19 (стандарт для ESP32).
   SCK: Пин 18 (стандарт для ESP32).
   
1.3 Сетевые настройки (SoftAP): 
   Контроллер создает собственную Wi-Fi сеть для подключения к интерфейсу:
   SSID: NanoNC
   Password: 12345678
   Port: 80 (HTTP) / /ws (WebSocket)
   
   Важные технические замечания: Ядро: Код настроен для работы с ESP32 Core v2.0.17.Таймер: Генерация шагов вынесена на аппаратный таймер 0, который принудительно запускается на Core 0 (ядро 0), чтобы не мешать сетевому стеку и основной логике.Аварийная остановка: Функция emergencyStop не только останавливает моторы, но и обязательно отключает шпиндель (пин 4). Взаимодействие с файлами G-кода происходит через SD-карту, подключенную по протоколу SPI.
